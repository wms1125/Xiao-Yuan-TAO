# 校园淘 · M2 技术选型与环境搭建

> 里程碑：M2 技术选型与环境搭建 ｜ 产出：`M2-技术选型与环境搭建.md` + `ai-log/001` + `ai-log/002`
> 本文档说明校园淘的技术选型理由、版本清单、环境搭建步骤、约定与踩坑记录。

---

## 一、选型总纲

校园淘属于「实验四」交付物，需在有限周期内交付一套**可运行、可演示、可交付**的完整交易闭环系统，并覆盖任务书要求的企业级能力。选型遵循三条原则：

1. **站在成熟框架上做业务**：以若依 RuoYi-Vue 为底座，复用其用户/角色/菜单/日志/监控等后台能力，业务模块集中精力做交易闭环。
2. **开箱即运行**：交付形态为 Windows 绿色一体化发行包，自带 JDK 与 MySQL，降低评审方的环境成本。
3. **依赖可隔离、可复现**：所有运行依赖不污染系统，Redis 采用内嵌方案避免外部安装。

## 二、选型对比表

### 2.1 基础框架

| 维度 | 选型 | 备选方案 | 选型理由 |
|------|------|----------|----------|
| 业务框架 | 若依 RuoYi-Vue 3.9.2 | 从零手写 Spring Boot 脚手架 | 若依自带权限、菜单、日志、监控、代码生成等后台能力，可快速搭建；招聘场景中覆盖率高，学习价值大 |
| 后端 | Spring Boot 4.1.0 + JDK 17 | Spring Boot 2.x + JDK 8 | JDK 17 为 LTS，Spring Boot 4.1 更贴近当前主流版本；若依 3.9.2 对 JDK 17 兼容良好 |
| 持久层 | MyBatis | JPA / MyBatis-Plus | 与若依原生一致，SQL 可控，便于手写乐观锁与原子扣款的定制 UPDATE |
| 安全 | Spring Security + JWT | Shiro + Session | 若依原生方案，无状态令牌适合前后端分离 |
| 前端框架 | Vue 3.5 + Vite | Vue 2 + Webpack | Vue 3 组合式 API，Vite 冷启动与热更新更快；与若依 3.9.2 前端一致 |
| UI 组件 | Element Plus 2.13 | Ant Design Vue | 与若依后台风格统一，组件生态完善 |
| 状态/请求 | Pinia + Axios | Vuex + fetch | Pinia 为 Vue3 官方推荐；Axios 与若依请求封装一致 |
| 图表 | ECharts | Chart.js | 若依监控页原生使用，复用现有能力 |

### 2.2 数据与缓存

| 维度 | 选型 | 备选方案 | 选型理由 |
|------|------|----------|----------|
| 数据库 | MySQL 8.0.40 | PostgreSQL / SQLite | 若依默认适配 MySQL；8.0 支持窗口函数、CTE，生态成熟；SQLite 不支持高并发写场景 |
| 缓存 | Redis（内嵌 embedded-redis） | 外部 Redis 服务 / Docker | 本系统使用 Redis 承担验证码、令牌、系统配置缓存。外部 Redis 需要单独安装且部分环境禁用 Docker/WSL；内嵌方案在应用启动时自动于 6379 拉起，进程退出自动关闭，**无需单独安装**，可复现性最强 |
| 连接池 | Druid | HikariCP | 若依原生使用 Druid，自带监控页面，便于演示 |
| 打包形态 | fat-jar（Spring Boot 可执行 jar） | war + 外部 Tomcat | fat-jar 可用 `java -jar` 一键启动，符合发行包一体化目标 |

### 2.3 运行与交付形态

| 维度 | 选型 | 备选方案 | 选型理由 |
|------|------|----------|----------|
| 运行平台 | Windows 绿色一体化发行包（campus-tao-dist） | 源码 + 环境搭建文档 | 打包自带 JDK 17 与 MySQL 8.0.40，三步脚本开箱运行，评审成本最低 |
| JDK | Adoptium 17.0.20.1 | Oracle JDK 17 | Adoptium 免费、可再分发，适合随发行包内置 |
| 前端依赖安装 | 国内镜像 npm | 官方源 | 国内网络直连官方源慢，改用国内镜像加速 |
| 启动方式 | 三个一键 bat 脚本 | 手工逐条命令 | 降低操作门槛，减少人为错误 |

> 说明：内嵌 Redis 为 Windows 版本，故发行包**仅支持 Windows**；Mac/Linux 需另行处理（本实验不承诺）。

## 四、环境搭建步骤（三步 bat）

发行包 `campus-tao-dist` 结构：

```
campus-tao-dist/
├─ jdk-17/            内置 JDK 17
├─ mysql-8.0.40/      内置 MySQL 程序（data 目录首次运行自动生成）
├─ campus-tao/        后端（已打包 ruoyi-admin.jar）
├─ campus-tao-ui/     前端源码（依赖由启动脚本自动安装）
├─ 1-初始化数据库.bat
├─ 2-启动后端.bat
└─ 3-启动前端.bat
```

> 前提：**必须解压到纯英文路径**（MySQL 在 Windows 上不认中文路径，会截断路径导致启动失败）。

### 步骤 1：`1-初始化数据库.bat`

- 初始化 MySQL 数据目录；
- 设置 root 密码为 `123456`；
- 导入 `sql/campus_tao_full.sql`（含 33 张系统表 + 业务表 + 演示数据）。
- 约 20~40 秒，出现「数据库初始化完成」即成功；**只需跑一次**。

### 步骤 2：`2-启动后端.bat`

- 命令行为 `java -jar` 启动后端，监听 8080；
- 同时自动拉起内嵌 Redis（6379）。
- 观察日志出现 `Started RuoYiApplication` 或 `Tomcat started on port 8080` 即成功。

### 步骤 3：`3-启动前端.bat`

- 首次自动执行 `npm install`（国内镜像，约 3~10 分钟，需联网），随后启动前端 dev，监听 8088；
- 之后再次运行会跳过安装直接启动；
- 看到 `Local: http://localhost:8088` 即成功。

访问：浏览器打开 `http://localhost:8088`，默认账号 **admin / admin123**。

## 五、端口与目录约定

### 5.1 端口

| 端口 | 用途 |
|------|------|
| 3306 | MySQL |
| 6379 | Redis（内嵌，应用启动自动拉起） |
| 8080 | 后端服务 |
| 8088 | 前端 dev |

前端经 Vite 代理把 `/dev-api` 转发到后端 8080。

### 5.2 目录约定

| 内容 | 位置 |
|------|------|
| 后端业务源码 | `campus-tao/RuoYi-Vue-master/ruoyi-system/src/main/java/com/ruoyi/campus/` |
| MyBatis 映射 | `ruoyi-system/src/main/resources/mapper/campus/` |
| 单元测试 | `ruoyi-system/src/test/java/com/ruoyi/campus/` |
| 前端页面 | `campus-tao-ui/src/views/campus/` |
| 前端接口封装 | `campus-tao-ui/src/api/campus/` |
| 建表脚本 | `campus-tao/sql/campus_tao_full.sql` |
| 集成测试脚本 | `campus-tao/e2e_business.py` |
| 文档 | `campus-tao/*.md`、`campus-tao/ai-log/` |

### 5.3 代码组织约定

后端业务统一置于 `com.ruoyi.campus` 独立包，分 `domain` / `mapper` / `service` / `controller` / `dto` / `exception`，**不污染若依原生代码**，便于后续升级框架时隔离影响面。

## 六、依赖隔离策略

| 依赖 | 隔离/供应方式 |
|------|---------------|
| JDK 17 | 随发行包内置（`jdk-17/`），不依赖系统 JAVA_HOME |
| MySQL 8.0.40 | 随发行包内置（`mysql-8.0.40/`），本地 data 目录，不安装系统服务 |
| Redis | 内嵌 embedded-redis，应用进程内拉起 6379，进程退出自动关闭 |
| 前端依赖 | 首次 `npm install` 装入 `campus-tao-ui/node_modules`，使用国内镜像 |
| Maven / 本地仓库 | 交付环境可能无 Maven、无 `~/.m2`；采用 fat-jar 原地重编译策略（见第四节与 ai-log/007） |

隔离目标：**发行包运行不写系统目录、不装系统服务**，卸载即删除目录，对宿主环境零残留。

## 七、踩坑记录

| 编号 | 现象 | 根因 | 解决 |
|------|------|------|------|
| P1 | 数据库初始化失败 | 路径含中文，MySQL 在 Windows 上截断路径 | 将发行包移动到纯英文路径后重跑 |
| P2 | 前端代理连不上后端 8080 | devtools 热重启令 Tomcat 落到随机端口 | 在 `application.yml` 关闭 devtools restart |
| P3 | 上传功能异常 | 上传路径原为绝对路径 `D:/ruoyi`（不存在） | 改为相对路径 `./uploadPath`，并同步刷新 jar 内 `application.yml` |
| P4 | `npm install` 卡死 | 前端原依赖 `sass-embedded`，其安装脚本会从 GitHub 下载原生二进制，不通 GitHub 的环境下卡死 | 改为纯 JS 的 `sass` |
| P5 | 验证码开关命令行参数无效 | 验证码开关在数据库 `sys_config`，不在 yml | 直接改 `sys_config.sys.account.captchaEnabled` |
| P6 | 交付机无 Maven 无法重新构建 | 交付机无 Maven、无本地 `~/.m2` 仓库 | 采用 fat-jar 原地重编译（解包 → javac 增量编译 → 重打内层 jar → 替换） |
| P7 | 重打内层 jar 后启动报 bean 缺失 | 重打时丢失 zip 目录条目，Spring Boot 嵌套 jar 资源解析失效、组件扫描扫不到类 | 补回目录条目后启动成功 |

> 踩坑的详细过程与验证见 `ai-log/001` ~ `ai-log/007`。
