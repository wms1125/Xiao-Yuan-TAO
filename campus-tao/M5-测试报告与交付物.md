## 二、接口/集成测试执行结果（E2E，RESULT = ALL_PASS）
执行 `python e2e_business.py`，采用**双账号**流程（admin 作卖家、ry 作买家），覆盖全链路与越权/超卖专项：

1. 双账号登录（admin、ry）→ 均返回 token
2. ry 沙箱充值 500 → 成功（首次自动创建账户行）
3. admin 发布商品（**故意伪造 sellerId=99**）→ 服务端强制改写为登录用户 1
4. ry 加入购物车（数量 2）→ 成功
5. ry 下单（显式购物车项）→ `下单成功`，订单号 `CT...`
6. ry 支付 → `支付成功`，沙箱余额 **500 → 440**（扣 60）
7. admin 发货 → `已发货`
8. ry 确认收货 → `已确认收货`
9. ry 评价 → `评价成功`
10. ry 申请售后（退货退款）→ `申请已提交`
11. admin 审核通过（**故意伪造 `handler=forged-hacker`**）→ `审核完成`，余额 **440 → 500**，库存 **3 → 5**（回滚一致）
11.1 复核售后单：库中审核人为 `admin`，前端伪造值被忽略
12. 防超卖：库存 1 的商品下单 2 件 → 拦截「库存不足」
13. C2C 卖方：ry（学生）发布商品 → 200 成功，卖家强制为本人（伪造 `sellerId=99` 仍落库为 2）
14. 权限收敛：ry 调售后审核接口 → 403（防自审自批）
15. **[v1.0.7] 物流轨迹**：通道状态查询、订单轨迹查询（本人可查）、匿名访问被拒(401)、他人订单被拒、外呼留痕仅管理员可查(ry → 403)、留痕命中短信与邮件两条链路且关联本单业务号

**断言校验**：
- PASS 商品发布服务端强制卖家身份：伪造 sellerId=99 → 落库为 1
- PASS 支付扣款金额正确：60
- PASS 订单列表归属过滤：ry 仅返回本人订单
- PASS 余额回滚一致：500.0 == 500.0
- PASS 库存回滚一致：5
- PASS 防超卖生效：库存 1 下单 2 件被拦截
- PASS C2C 卖方：ry 发布商品成功且卖家身份强制为本人(2)
- PASS 权限收敛：ry 调用售后审核（管理员接口）返回 403
- PASS 审核人防伪造：请求传 `handler=forged-hacker` → 库中审核人仍为 `admin`（取自登录态）

> 结论：业务一致性、资金与库存回滚、防超卖、越权拦截均符合预期。

## 三、动态菜单权限收敛校验（API 级）

|------|-----------|----------|----------|--------|----------|----------|----------|
| admin | 可见 | 可见 | 可见 | 可见 | 可见 | 可见 | 可见 |
| ry（买家） | 可见 | 可见 | **不可见** | 可见 | 可见 | 可见 | 可见（无审核按钮权限） |

> 说明：菜单不再硬编码于前端 `router`，改由后端菜单表驱动；ry 已授予商品新增/修改/删除（2100~2102，支持学生自主发布并维护自己的商品），未授予分类管理（2002、2103~2105）与售后审核（2113），故前端不渲染对应入口，后端亦返回 403，形成双重拦截。

## 四、防超卖专项说明
`CampusProductMapper.decreaseStock`：
```sql
UPDATE campus_product SET stock = stock - #{count}, version = version + 1
WHERE id = #{id} AND stock >= #{count}
```
- 并发场景下，只有 `stock >= count` 的更新能成功（影响行数=1），其余返回 0 → 服务层抛异常并回滚，从根本上杜绝超卖。
- 已被 E2E 用例（库存1、下单2件）验证拦截。

## 十二、补充验证：工程流水线加固（v1.0.10，2026-10-15）
**动机**：企业级评估中「工程化开发规范度」得分最低（72/100），短板集中在流水线——测试只验"跑得通"不验"覆盖到什么程度"，且生产部署路径缺失（前端生产接口前缀为 `/prod-api`，但交付包没有任何反向代理配置）。

**做法**：

## 十三、补充验证：前端代码规范基线（v1.0.11，2026-10-15）

**做法**：
1. **先摸清存量风格再定规则**：统计得出项目既有主流写法为「无分号、单引号、2 空格缩进」，故 Prettier 配置即按此设定（`semi:false`、`singleQuote:true`、`tabWidth:2`、`trailingComma:'none'`、`endOfLine:'auto'`），使基线重排**尽量贴近原貌**而非推倒重来。
2. **`printWidth` 以实测最小扰动取值**：80 / 100 / 120 三个候选分别需重排 **157 / 152 / 151** 个文件、改动 **21373 / 17901 / 16324** 行，取 **120**。`endOfLine:'auto'` 保留各文件既有行尾（仓库 `.gitattributes` 归一为 LF），避免 EOL 噪音混进 diff——单文件验证过 Prettier 不改变 CRLF 文件的行尾。
3. **基线格式化独立成一个提交**：纯机械重排、不改任何标识符与逻辑，便于单独评审；提交前复跑单测 44/44 与生产构建均通过，证明重排未破坏行为。
