# ai-log 009 · 依赖漏洞（CVE）专项治理

> 里程碑：M7（依赖安全） ｜ 主题：CVE 扫描取证、后端框架升级、前端依赖收敛、残余风险判定 ｜ 记录方式：AI 辅助留痕

## 里程碑目标

M1~M6 已把业务闭环、权限边界与可观测性补齐，SBOM 也回答了"用了哪些组件、许可是否合规"，但**始终没有回答"这些组件有没有已知漏洞"**（v1.0.5 的 `[未发布]` 中如实挂着这一条）。本次把这块补上：

- **能扫**：引入可复现的扫描手段（前端 `npm audit`、后端 `osv-scanner` + CycloneDX BOM），并把结果口径写进 SBOM。
- **能修**：把可升级的漏洞真正修掉，而不是只出一份报告。
- **能说清**：修不掉的部分要给出**可验证的判定依据**，而不是一句"风险可接受"。

## 关键决策与取舍

| 决策点 | 选择 | 备选方案 | 取舍理由 |
|--------|------|----------|----------|
| 后端扫描工具 | `osv-scanner` v2.7.0 扫描已有 CycloneDX BOM | OWASP Dependency-Check（`mvn org.owasp:dependency-check-maven:check`） | 项目已有 CycloneDX BOM（SBOM 交付物），直接复用它扫描，**一份物料清单同时服务许可合规与漏洞扫描两条线**，避免引入第二套依赖清单；且 OWASP 插件首次运行需下载 NVD 全量库（数百 MB），交付机联网成本高 |
| 前端扫描口径 | 同时看 `npm audit`（全量）与 `npm audit --omit=dev`（生产依赖树） | 只看全量 | 全量含构建期工具链（vite/插件/打包器等）。对**交付出去的应用**真正有意义的是生产依赖树——本次升级后 `--omit=dev` 为 **0**，全量仍有 5 项 high 但全在 devDependencies。分两个口径报告，避免"用构建期告警否定交付物安全"或反之 |
| 后端升级方式 | 整体升 `spring-boot.version` 4.1.0 → 4.1.1 **并**对 Tomcat/Jackson 显式声明补丁版本 | 只升 Spring Boot；或逐个手改依赖版本 | 只升 Spring Boot 补不全（4.1.1 的 Tomcat 仍是 11.0.24 < 修复线 11.0.25、Jackson 3 仍是 3.1.5 < 3.1.6）；逐个手改依赖版本会与 BOM 的版本管理打架，且日后维护成本高。**"BOM 升级 + 少数几项显式声明"是最小改动面** |
| 覆盖声明的位置 | 放在根 `pom.xml` 的 `dependencyManagement` 中、**Spring Boot BOM 之前** | 放在 `<properties>` 里覆盖 `tomcat.version` 等属性 | 实测**属性覆盖对 import 型 BOM 无效**（详见踩坑表）；只能靠"直接声明优先于 import"的规则生效 |
| 前端告警的处置 | 可升的全升；剩余 5 项**接受并书面记录**残余风险 | 为清零而降级 `vite-plugin-svg-icons` 至 0.1.0 | npm 给出的"修复"是降级，属**假修复**（会破坏图标管线、丢失功能）。真正的判据是该告警是否**可被外部输入触发**：这 5 项全在构建期、输入是自家可信 SVG 源码、且根因 `braces` 上游**无任何补丁版本**（最新 3.0.3 仍命中 `RANGE=*`） |
| 幽灵依赖的处理 | 把 `fast-glob` **显式声明**为 devDependency | 保留 `overrides` 或回退 `unplugin-auto-import` 版本 | `vite-plugin-svg-icons` 自己没声明却运行时 `import 'fast-glob'`，原本靠 `unplugin-auto-import@0.18` 的依赖树"顺带"提升安装。显式声明是**修正而非绕过**——它把隐性依赖变成显式契约，还要在依赖升级后保持可构建 |
| 同名坐标告警的处置 | 核查代码后判定误报，并写入 SBOM | 直接计为未修复高危，或静默忽略 | `com.ruoyi:ruoyi-common` 这一坐标被 RuoYi-Vue 与 RuoYi-Cloud **两个产品共用**。判定依据必须是可复核的事实（本项目该模块无 Web 端点、通告针对的是另一个产品），否则就只是"我们觉得没事" |

## 踩坑与解决

| 现象 | 根因 | 解决 |
|------|------|------|
| **在 `<properties>` 里覆盖 `tomcat.version` / `jackson-bom.version` 完全无效** | 用 `import` 引入的 BOM，其**内部属性在 BOM 自己的模型里插值**，不随引入方 pom 的同名属性改变；只有 `spring-boot-starter-parent` 作父 POM（继承）时属性覆盖才有效 | 改为在**本模块 `dependencyManagement` 中、Spring Boot BOM 之前**显式声明补丁版本（Maven 规则：本 pom 的直接声明优先于 import）。用 `mvn dependency:tree` 实测确认解析结果从 11.0.24/3.1.5/2.21.5 变为 11.0.27/3.1.7/2.21.7 |
| `vite build` 报 `Cannot find package 'fast-glob'` | `vite-plugin-svg-icons` 的**幽灵依赖**：自身 `package.json` 未声明 `fast-glob`，依赖升级后原先"顺带装上"的包消失，但其代码仍 `import` 它 | 显式声明 `fast-glob` 为 devDependency（顺带解决了该链条里的 5 项告警之一） |
| `osv-scanner` 报 `Invalid SBOM filename` | v2 要求 SBOM 文件名符合规范（CycloneDX 需 `*.cdx.json`），`backend-bom.json` 不合规 | 扫描时用副本 `backend-bom.cdx.json`；交付物仍保留可读的 `backend-bom.json` |
| CycloneDX 插件在 `-o` 离线模式直接报错 | `makeAggregateBom` 需联网从 deps.dev 拉取许可信息，插件主动拒绝离线执行（`Goal requires online mode`） | SBOM 生成单独走联网模式；生成后清理 `.tools/m2-repo` 中新增的 `_remote.repositories` / `*.lastUpdated`，保证 `-o` 离线构建依旧可复现 |
| `search.maven.org` 的 search API 返回的版本明显陈旧（如 spring-webmvc 最高只到 7.0.0-M6） | 该 API 的索引滞后于制品库 | 改用 `repo1.maven.org/maven2/**/maven-metadata.xml`（权威制品元数据）确认最新版本与修复线 |
| 后端 `mvn` 报 `JAVA_HOME is not defined correctly` | 交互式 PowerShell 会话未继承交付包内的 JDK，命令行直接调 `mvn.cmd` 缺 JAVA_HOME | 在脚本中显式 `set JAVA_HOME=<交付包内 JDK>`（交付机的 `verify.bat` 已内置该逻辑，本次自建脚本照抄） |

2. **残余 1 项的判定依据**（可复核）：`com.ruoyi:ruoyi-common@3.9.2` 命中 `GHSA-vp22-232w-h9x8` / CVE-2022-4348，摘要为「RuoYi-**Cloud** Cross-site Scripting」，影响范围 `last_affected: 4.6.2`，上游补丁指向 RuoYi-Cloud 的 gitee PR #224。
   ```
   $ grep -rn "@RestController|@Controller|@RequestMapping" ruoyi-common/src/main/java/com/ruoyi/common
   → 无任何匹配（仅存在一个无映射注解的 BaseController）
   ```
   即：本项目 `ruoyi-common` 模块**不含 Web 端点**，与该通告所述"JSON Handler"攻击面无关；这是两个产品共用 Maven 坐标导致的碰撞，且 OSV 中该通告**无 `fixed` 事件**（无法通过升级消除）。

## 未覆盖 / 后续建议

- **前端 5 项 high 仍未清零**，属已记录的接受项。若要彻底移除，可选方案是以 `unplugin-icons` 替换 `vite-plugin-svg-icons`（本次未实施，未列入承诺）。
- **漏洞库有时效性**：本次结论是"截至今日、针对当前版本集合"的。建议在 CI 中**定期重扫**（`npm audit --omit=dev` + `osv-scanner`），而不是把扫描当成一次性动作。
- **后端 BOM 不含测试作用域依赖**（`-DincludeTestScope=true` 可另行生成），本次扫描覆盖的是编译/运行期依赖。
- **首次前端扫描踩到本地 npm 代理**：本机全局 registry 指向一个已停用的本地代理端口，安装/审计需显式 `--registry=https://registry.npmjs.org/` 绕过。交付机若处于无网环境，前端依赖升级需预先将包同步进本地缓存。
- 后端升级为**补丁级**（4.1.0→4.1.1）与**补丁版本显式声明**，未做跨小版本跃迁；后续若 Spring Boot 出 4.2.x 正式版，可再评估一次整体升级。
