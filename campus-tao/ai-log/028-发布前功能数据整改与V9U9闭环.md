## 2. 关键实现

### 2.1 四个被漏掉的功能缺陷（P0）
- **收藏跳 404**：`favorite/index.vue` 的 `goDetail` 走 `/campus/mall/detail/{id}`，与菜单里
  注册的真实路由 `/campus/mall-detail`（隐藏菜单 2009）不一致。改为 `path + query` 跳转。
  这类"页面能渲染、点下去 404"的缺陷，单元测试与"页面截图"都抓不到。
- **售后驳回后状态自相矛盾（P0-2）**：驳回分支原写死 `setStatus(3 已完成)`，既丢失申请前的
  原状态（可能是已发货 2），又不写 `finish_time` → 出现「已完成但无完成时间」的订单。
  修法：申请时把订单原状态写入 `campus_aftersale.order_status_before`，驳回时还原；并保证
  「已完成方有 finish_time，其它状态不残留」。历史无该字段的数据保守回退为已完成。
- **卖家看不到/不能同步自己订单的物流（P0-3）**：`CampusLogisticsController.canAccess`
  只判「买家本人 or 管理员」，卖家被挡；`/sync` 还挂 `campus:order:edit`（管理端动作）。
  修法：归属校验补卖家本人；`/sync` 去掉 PreAuthorize，改标
  `@SelfServiceEndpoint("仅订单买家/卖家本人或管理员：方法内 canAccess 校验订单归属…")`。
  这里踩到一条既有门禁：权限注解守护测试要求所有变更类端点声明
  `@PreAuthorize / @Anonymous / @SelfServiceEndpoint` 三者之一——去掉 `@PreAuthorize` 后
  必须给出"为什么可以不带按钮权限"的书面理由，门禁才会放行（否则报
  `CampusLogisticsController#sync` 缺声明）。**门禁按设计逼出了自证**。
- **卖家信息校验收紧（P2）**：`initiateDirectPay` / `attachSellerPayQr` 只判 `sellerId == null`，
  `seller_id = 0` 这类脏值会被当成有效卖家。收紧为 `null || <= 0`。

### 2.2 触达与对账（P1）
- **业务事件站内通知 5 类**：下单（→卖家）、支付成功（→买家+卖家）、确认收货（→卖家）、
  取消订单（→卖家，三个取消分支同一出口）、售后申请（→卖家）。
  新增 `ICampusOrderService.resolveSellerIds(orderNo)`：按订单项查商品取 `sellerId`，
  用 `LinkedHashSet` 去重并排除 null / <=0 / 买家本人——支持跨卖家订单通知到多个卖家。
- **支付流水表（P1-3）**：`campus_payment_record` 落 `pay` / `refund` / 渠道回调三条路径，
  保留 `channelTradeNo`。此前代码注释里承认该字段"无处落库、只能丢弃"，对账无从谈起。
  设计取舍：流水写入包在 try/catch 里**只告警不抛出**——支付/退款已由渠道侧完成，
  这里抛异常会让用户看到"支付失败"但钱已扣。
- **直付确认留痕（P1-2）**：`pay_confirm_time` / `pay_confirm_by`；`confirmPayIfAwaitConfirm`
  由 2 参改 4 参，确认人与时间随原子 UPDATE 一并落库。
- **卖家维度索引（P1-4）**：`campus_order(seller_id, create_time)`。

### 2.3 迁移与回滚（本批最重要的交付修复）
- **V9** 沿用 V6~V8 的幂等判存写法（`information_schema` 判存在 → 拼 SQL → PREPARE/EXECUTE），
  覆盖加列、加索引、建表、启用定时任务。
- **U9 是补上的缺口**：`db/rollback/` 只有 U1~U8，而 `rollback.sh` 按版本号找 `U<n>__*.sql`。
  回滚到 V9 之前会**在"找不到版本 9 的回滚脚本"处直接中止**，且不会执行后面的
  `DELETE FROM flyway_schema_history` → 库结构未回滚干净、版本记录却还声称 V9 已应用。
  补 U9 后实测 `U9 → V9 → V9` 往返：探测位（流水表 / pay_confirm 列 / order_status_before /
  idx_seller_time / 启用的 job）序列 `1 2 1 1 2 → 0 0 0 0 0 → 1 2 1 1 2 → 1 2 1 1 2`，
  三次退出码均为 0（第二次 V9 全部"已存在，跳过"）。
- `verify_flyway.sh` 的断言同步扩到 V9：表数 48→49、新增 5 条 V9 断言、V9 索引纳入
  「回滚无残留」与「重放恢复」核对，并把 `campus_payment_record` 加进逐表核对的预期新增表清单。
