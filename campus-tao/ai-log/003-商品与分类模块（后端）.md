# ai-log 003 · 商品与分类模块（后端）

> 里程碑：M3（业务闭环 · 分块一） ｜ 主题：商品与分类模块后端实现 ｜ 记录方式：AI 辅助留痕

## 里程碑目标

完成校园淘业务闭环的第一段后端能力：

- 商品域：发布、编辑、删除、上下架、列表/详情查询；
- 分类域：树形分类的新增、编辑、删除；
- 建立 `com.ruoyi.campus` 独立包与四层结构，作为后续购物车/订单/售后模块的范式；
- 引入 DTO + Bean Validation 参数校验与统一 `AjaxResult` 响应。

## 关键决策与取舍

| 决策点 | 选择 | 备选方案 | 取舍理由 |
|--------|------|----------|----------|
| 代码组织 | `com.ruoyi.campus` 独立包，domain/mapper/service/controller 分层 | 直接改若依原生包 | 不污染框架代码，便于升级与维护隔离 |
| 权限控制 | 写接口 `@PreAuthorize("@ss.hasPermi('...')")` | 只在菜单层控制 | 后端二次校验，无权限返回 403，与前端形成双重拦截 |
| 商品状态 | `status` 字段：0 下架 / 1 上架 | 用布尔删除标记 | 明确上下架语义，上架商品才可被加购 |
| 分类结构 | `parent_id` + `sort` 树形 | 扁平分类 | 支持多级分类与自定义排序 |
| 卖家归属 | 一律取自服务端 `SecurityUtils.getUserId()/getUsername()` | 采信前端传入 sellerId | 归属人不可被前端篡改 |
| 图片与成色 | `images` 存储图片、`condition_level` 1~5 表示成色 | 自由文本描述成色 | 结构化字段便于前端渲染与筛选 |

商品模块权限字符串：`campus:product:list / add / edit / remove`；分类模块权限字符串：`campus:category:list / add / edit / remove`。

## 踩坑与解决

| 现象 | 根因 | 解决 |
|------|------|------|
| 商品发布时卖家可被伪造 | 早期实现采信了前端传入的 `sellerId` | 改为在服务层强制改写为登录用户（`SecurityUtils.getUserId()`），前端传值仅作为无效输入忽略 |
| 图片上传报错 | 上传路径原为不存在的绝对路径 `D:/ruoyi` | 改为相对路径 `./uploadPath`，并刷新 jar 内 `application.yml` |
| 分类层级展示异常 | `parent_id` 未按树形组装 | 服务层按父子关系组装分类树后再返回前端 |

## 验证证据

1. 身份防篡改（E2E 步骤 3）：admin 作为卖家发布商品时**故意伪造 `sellerId=99`**，落库后校验：

```
PASS 商品发布服务端强制卖家身份：伪造 sellerId=99 → 落库为 1
```

2. 列表查询：商品列表接口返回完整商品字段（标题、价格、原价、成色、库存、状态等）。

3. 参数校验（单元测试）：JUnit 5 中 11 个 DTO 参数校验用例覆盖必填项、数值范围等，全部通过；校验失败返回中文提示。

4. 权限收敛（E2E 专项）：普通买家 `ry` 调用商品发布接口返回 403：

```
PASS 权限收敛：ry 越权调用商品发布返回 403
```

5. 分类维护：新增/编辑/删除分类经前端代理验证可正常落库与展示。
