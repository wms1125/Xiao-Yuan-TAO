# ai-log 007 · 企业级加固与交付打包

> 里程碑：M4（企业级能力加固）+ M5（交付打包） ｜ 主题：六维加固、fat-jar 原地重编译与交付验证 ｜ 记录方式：AI 辅助留痕

## 里程碑目标

在 M3 业务闭环之上完成企业级加固，并产出可交付的发行包：

- 从安全、一致性、可靠性、性能、工程化、运维六个维度加固，覆盖任务书「≥6 项企业级能力」要求；
- 在**交付机无 Maven、无本地 `~/.m2` 仓库**的条件下完成代码改动的重新编译与打包；
- 交付 Windows 绿色一体化发行包 `campus-tao-dist` 并完成端到端回归。

## 关键决策与取舍

| 决策点 | 选择 | 备选方案 | 取舍理由 |
|--------|------|----------|----------|
| 安全加固 | Spring Security + JWT；写接口 `@PreAuthorize`；身份取服务端 `SecurityUtils`；归属校验 | 仅前端菜单控制 | 后端二次校验，前端无法篡改归属人，越权返回 403 |
| 验证码策略 | 开关读自 `sys_config`，演示环境置 false | 硬编码/命令行参数 | 符合若依实际读取位置，演示便捷、生产可开 |
| 一致性加固 | 关键动作统一 `@Transactional(rollbackFor = Exception.class)` | 分散事务 | 库存与订单、退款与回补同事务，杜绝半完成 |
| 可靠性加固 | 乐观锁防超卖、支付幂等、账户原子扣款、状态机约束 | 仅应用层校验 | 数据库原子判断，并发下不超卖、不超扣 |
| 工程化加固 | 业务异常统一抛框架 `ServiceException`；另加全局异常处理器兜底未预期异常 | 直接抛堆栈 | 统一返回 code/msg，避免堆栈泄露 |
| 重编译方式 | **fat-jar 原地重编译** | 安装 Maven 重新构建 | 交付机无 Maven、无 `~/.m2`，原地重编译最可行 |
| 内层 jar 重打 | 使用保留目录条目的方式重打 `ruoyi-system` 内层 jar | 直接压缩文件列表 | 保留 zip 目录 entry 才能让 Spring Boot 正确解析嵌套 jar |

改动与验证要点：新增 `CampusGlobalExceptionHandler`（`@RestControllerAdvice`，兜底未预期的 `RuntimeException`）；业务异常统一由框架 `ServiceException` 处理；`payOrder` 增加幂等判断；JWT 密钥支持 `${JWT_SECRET:演示默认值}` 注入。

## 踩坑与解决

| 现象 | 根因 | 解决 |
|------|------|------|
| 交付机无 Maven 无法重新构建 | 无 Maven、无本地 `~/.m2` 仓库 | 采用 fat-jar 原地重编译：解包 `ruoyi-admin.jar` → 用 `javac` 增量编译改动类（classpath 指向 `BOOT-INF/lib` 下全部 jar）→ 重打 `ruoyi-system` 内层 jar → 替换进 fat jar |
| **启动报 `ISysConfigService` bean 缺失** | 重打内层 jar 时一度丢失了目录条目（zip 目录 entry），导致 Spring Boot 嵌套 jar 包资源解析失效、组件扫描扫不到类 | 补回目录条目后重新打包，启动成功。这是典型的嵌套 jar 打包陷阱 |
| E2E 单账号无法跑通 | `createOrder` 有「不能购买自己发布的商品」拦截；普通用户 `ry` 若无校园淘菜单权限会返回 403 | 必须先补菜单/角色 SQL，再将 E2E 由单账号改造为**双账号**（admin 卖家 / ry 买家） |
| 命令行改验证码开关无效 | 开关在数据库 `sys_config`，不在 yml | 直接更新 `sys_config.sys.account.captchaEnabled` |
| 上传路径失效 | 绝对路径 `D:/ruoyi` 不存在 | 改相对路径 `./uploadPath`，并刷新 jar 内 `application.yml` |

## 验证证据

1. 重编译后启动成功：

```
Started RuoYiApplication
Tomcat started on port 8080
```

2. 六维加固回归：E2E 全链路执行 `python e2e_business.py`，输出：

```
RESULT = ALL_PASS
```

覆盖双账号登录 → 充值 500 → 发布商品（伪造 sellerId=99 被改写为 1）→ 加购 → 下单 → 支付（余额 500→440，扣 60）→ 发货 → 收货 → 评价 → 申请售后 → 审核通过（退款，余额回 500，库存回补 5）→ 防超卖（库存 1 下单 2 件被拦截）→ 权限收敛（ry 调商品发布 403、ry 调售后审核 403）。

3. 单元测试：JUnit 5 位于 `ruoyi-system/src/test/java/com/ruoyi/campus/`，两个测试类共 15 个用例全部通过（11 个 DTO 参数校验用例 + 4 个账户原子扣款 JDBC 用例）。可在无 Maven 环境下用 JUnit Platform Console Standalone 运行；接入 Maven 后 `mvn test` 可执行。

4. 健康检查：若依原生未引入 Actuator，存活探针以 `curl http://localhost:8080/captchaImage` 返回 200 为准；启动期打印端口与内嵌 Redis 状态。

5. 交付打包：`campus-tao/`（源码、SQL、文档）与 `campus-tao-ui/` 归入发行包 `campus-tao-dist`，配合三步脚本可开箱运行。
