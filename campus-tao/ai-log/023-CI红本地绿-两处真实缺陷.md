# 023 · P0-2 推送后 CI 抓出两处真实缺陷（自述不算证据的回报）

## 1. 目标与结论
P0-2（v1.0.19，`e84c6b3`）在本地 243 后端 + 167 前端用例全绿、五道前端门禁全绿后推送，指望 CI 独立重验。
**结论**：CI 最终 `failure`，6 个 job 中 2 个红——但红得有价值：它抓出了本地绿、远端红的两条真实缺陷。

- 前端「单元测试 + 覆盖率门禁」：167 用例**全过**，却因 **1 个 unhandled promise rejection** 退出码非 0 → `Error: network`。
- 数据库迁移与回滚：迁移本身 `BUILD SUCCESS`，却因**验证脚本基线停留在 V2** 把 V3 的合法增量判为「非预期差异」→ job 红。
- 后端构建/单测、容器起栈、依赖漏洞扫描、端到端业务回归 4 个 job 全绿；**e2e 在远端 MySQL 服务容器下 PASS**，即 P0-2 端到端断言已通过重验。

## 2. 关键实现（修复）
- `src/views/campus/mall/index.vue` 的 `loadHistory()`：原 `listSearchHistory(10).then(...).finally(...)` 缺 `.catch`。补
  `.catch(() => { searchHistory.value = [] })`——失败静默降级为「空态」，不再把 rejected promise 抛到全局。
- `db/tools/verify_flyway.sh`：
  - 步骤标题 `空库执行迁移（V1 + V2）` → `（V1 + V2 + V3）`；
  - 迁移成功断言 `Successfully applied 2 migrations` → `3 migrations`（两处：首次迁移与回滚后重放）；
  - 版本记录断言 `1,2` → `1,2,3`。
- `db/tools/compare_migration.sh`：`EXPECT_DELTA` 由 `sys_menu=9 sys_role_menu=9` → `=12 =12`，注释补明 V2 贡献 9、V3 贡献 3。

## 3. 本轮抓到的真实缺陷
1. **前端未捕获异常是真缺陷**（非脚本问题）：搜索历史是搜索框聚焦主流程上的旁路，任何接口失败都会 `Uncaught (in promise)`。浏览器控制台会报错、且可能打断聚焦渲染——生产环境真实可见，不是 CI 误报。修复后本机 `vitest run` 与 `test:coverage` 均 0 error。
2. **验证脚本过期是真风险**：若放任，任何后续新增迁移（V4…）都会让该 job 持续误红，掩盖真正的迁移错误。本次把 V3 的净贡献（3 菜单行 + 3 角色权限行，与 V2 的 9 累计 12；**不新增表，表数仍 47**）落到脚本注释里，后续维护者改 V4 时一眼能照着加。

## 4. 验证
- 前端（本机，managed Node 22）：`vitest run` **10 文件 / 167 用例 / 0 失败 / 0 错误**；`test:coverage` 全量 stmt 67.93% / branch 64.30% / func 73.41% / line 69.36%，阈值未回退。
- 后端：`mvn -B verify` 仅依赖既有 243 用例，本次未改后端代码，不受影响。
- 数据库迁移与回滚 job：**未能本机重跑**（MySQL 已停、无授权重启），依赖 1.0.20 推送后 CI 服务容器重验；脚本改动按「V3 净增 12 行、表数不变」的数学关系逐行核对，逻辑自洽。
- e2e：CI 远端 PASS，P0-2 端到端断言闭环，本地停服不再构成遗留项。

## 5. 未纳入本轮
- 数据库迁移 job 的**远端重验**需等 1.0.20 入 main 后由 CI 执行（本机无 MySQL，且用户明确要求不重启验证用 MySQL/后端）。
- 未动 P1-3（门禁口径分支 54.98% → 60%）：本轮是 P0-2 的收尾修复，不混入覆盖率改造，保持提交原子性。

## 6. 方法论小结
- **「自述不算证据」不是口号**：本地绿 + CI 红，是这套规范最直接的一次变现。两处红都是"本地能跑、远端暴露"的真实问题。
- **负向用例自带信息量**：本次 unhandled rejection 正是由 `mockRejectedValue(new Error('network'))` 这条"查询失败时不应阻断聚焦"的负向用例暴露的——若没有这条负向用例，`listSearchHistory` 的 reject 路径根本不会被触碰，缺陷会一直潜伏到生产。
- **门禁脚本也要随迁移演进**：迁移 job 的断言写死了版本号与种子增量，V3 落地时同步更新，否则门禁从"保护网"退化为"噪音源"。
- **数据口径要写清**：1.0.19 记的 59.53% 是 JaCoCo CSV 全口径（含 domain/mapper），而 `jacoco:check` 门禁口径（排除 domain/mapper）实为 54.98%。两者阈值都过，但"距 60% 仅 0.47 点"的说法基于错误基数，已更正。
