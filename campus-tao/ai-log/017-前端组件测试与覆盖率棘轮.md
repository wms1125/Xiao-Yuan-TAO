# 017 · 前端组件测试与覆盖率棘轮

> 版本：v1.0.14（2026-10-16）
> 对应交付项：《校园淘-提升评分行动计划》**T3 · 前端组件测试（jsdom + @vue/test-utils）**

## 目标

v1.0.13 已如实记录「**前端组件测试仍为 0**」：`vitest.config.js` 是 `environment: 'node'`，没有任何组件级用例，本轮新增的分页与概览联动（`refresh()`、`statsCount()`、`queryParams.pageNum` 归位）**只靠人工浏览器实测**，没沉淀成回归防线。

本次要做的是把"页面行为"变成自动化用例，并把前端覆盖率门禁从"只盖纯逻辑层（接口封装 + 工具函数）"扩到"覆盖页面行为"，门禁棘轮由 **行 25%** 上调到 **40%**。

## 关键决策与取舍

| 决策 | 做法 | 理由 |
|---|---|---|
| 不挂真实 Element Plus | 自建 `tests/unit/support/element-stubs.js` 轻量替身 | `el-table`/`el-scrollbar` 依赖 jsdom 未实现的 `ResizeObserver`，真实挂载要先补 polyfill；且真实挂载会把用例变成"验证 Element Plus 自己"，与本次要验证的业务联动无关 |
| 替身"结构保真、能力最小" | 需渲染处渲染默认插槽；`el-table`↔`el-table-column` 用 provide/inject 按行调用列的 scoped slot；`el-form` 暴露 `validate`/`resetFields` | 只有渲染了插槽，模板里的绑定表达式才会被求值，覆盖率才有意义；只有列的 scoped slot 收到 `{row}`，模板里的 `scope.row.xxx` 才不会抛错 |
| 环境按文件切换 | 组件用例首行 `// @vitest-environment jsdom`，其余文件仍走默认 `node` | Vitest 3 已弃用、**Vitest 4 直接移除** `environmentMatchGlobs`；按文件声明是该能力替代方案里最直观的一种，且纯逻辑用例不必为 DOM 付启动成本 |
| 测试配置与构建配置分离 | `vitest.config.js` 只挂 `@vitejs/plugin-vue` | 压缩、图标、自动导入等构建期插件与测试无关，带进来只会拖慢启动 |
| 门禁上调留余量 | 语句 24→45、分支 23→45、函数 32→55、行 25→40（实测 50.17/50.35/60.93/51.27） | 行覆盖率按计划硬指标抬到 40%，其余同步上调；阈值比实测低若干百分点，门禁的职责是拦住覆盖塌方，不是拦掉无关改动的正常抖动 |

## 踩坑与解决

1. **把 `.vue` 写进 `coverage.include` 后首次运行报 `Failed to parse …/index.vue. Excluding it from coverage.`**
   起初以为是 SFC 无法被 v8 统计，实际是 `coverage.all`（默认 `true`）的**预插桩**行为：它会对"本轮测试没有加载过"的白名单文件直接从磁盘读源码做插桩，而 v8 插桩器解析不了 SFC 源文件。**一旦用例真正 `import` 该组件，它就走上正常的模块流水线（经 vite 转换 + sourcemap 回映射），该报错自然消失**——所以正确顺序是"先写用例、再把它纳入白名单"，而不是先改配置。
2. **`provide` 下发数组导致列替身永远渲染不出行**
   最初写成 `provide('elTableRows', props.data)`，但 `:data` 绑的是 ref，列表加载完成后数组引用会被**整体替换**；setup 阶段取到的永远是挂载时的空数组。改为下发取值函数 `provide('elTableRows', () => props.data)`，在渲染时现取，行数据才能跟上响应式更新。
3. **`inheritAttrs` 默认继承 + 手动展开 `attrs` 让 `@click` 触发两次**
   替身里手动把 `attrs` 展开到根元素（为了让父组件挂的 `@click` 落到 DOM 上），同时保留默认的属性继承时，Vue 会把同一批 attrs **再 merge 一次**，事件处理器被合并成函数数组从而执行两遍。替身统一声明 `inheritAttrs: false` 后解决。
4. **`vitest.config.js` 漏挂 `@vitejs/plugin-vue`**：不挂则 `.vue` 不会被编译，`import Xxx from '@/views/…/index.vue'` 直接失败。测试配置虽然要和构建配置分离，但 SFC 编译这一条是必须保留的最小交集。

## 验证证据

- **用例规模**：前端用例 **48 → 66**（新增 `views.campus.order.test.js` 10 例、`views.campus.aftersale.test.js` 8 例），**66/66 全绿**。
- **覆盖率**：语句 **50.17%** / 分支 **50.35%** / 函数 **60.93%** / 行 **51.27%**（v1.0.13 为 25.04 / 23.61 / 35.57 / 26.2）；两个页面自身 行 **91.19%**（订单）/ **94.4%**（售后）。四项门禁通过。
- **负向验证 A（门禁真会拦）**：`npx vitest run --coverage --coverage.thresholds.lines=90` → 退出码 **1**，日志 `ERROR: Coverage for lines (51.27%) does not meet global threshold (90%)`。
- **负向验证 B（用例真在断言新行为）**：
  - 删掉 `order/index.vue` 中 `handleStatusFilter` 的 `queryParams.pageNum = 1` → 「切换状态筛选」用例失败（`expected { pageNum: 3, … } to match object { pageNum: 1, … }`）；
  - 把 `aftersale/index.vue` 的 `handleQuery` 由 `refresh()` 改为只 `getList()` → 「按订单号搜索」用例失败。
  - 两处改回即恢复 66/66 全绿，`git status`/`git diff` 确认源码零残留。
- **其余门禁**：`format:check` 通过；eslint **0 error / 161 warn**（与基线逐项一致）；`build:prod` 退出码 0。
- **依赖面**：新增 `jsdom` + `@vue/test-utils` 共 50 个包；`npm audit` 全量与 `--omit=dev` 均 **0 项**；lock 中 `resolved` 全部为 `registry.npmjs.org`。

## 未纳入本轮（如实记录）

- **只覆盖了订单页与售后页**：其余校园淘页面（商品 / 购物车 / 分类 / 沙箱账户 / 站内通知 / 外呼留痕）仍无组件用例，覆盖率白名单也尚未纳入它们。
- **观察项：两个页面的 `getStats()` 只有 `.then()` 没有 `.catch()`**：概览请求失败会产生未处理的 Promise rejection，而列表侧 `getList()` 有 catch，两者行为不一致。本轮按"只测试、不改业务"处理，用例亦刻意不构造概览失败分支，以免把既有行为固化成"这就是对的"。
- **`@SpringBootTest` 集成测试仍为 0**：与 v1.0.13 结论一致，SQL 层已由 `CampusMapperSqlIntegrationTest` 兜住，事务代理 / AOP / PageHelper 分页拦截级别仍由 `e2e_business.py` 兜底。
- **CSS 文字错行修复的浏览器视觉验证仍未完成**：改法有据（`letter-spacing` 导致的标签折行 + 表头 `.06em` 字距），前端四道门禁全通过，但**未取得可信的页面实测证据**，故不能声明"页面实测确认"。
