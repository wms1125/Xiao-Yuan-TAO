## 一、里程碑目标

M3 的目标是把 M1 定义的需求、M2 选定的技术栈，落成一套**买家与卖家都能真实走通**的二手交易系统：

1. **交易主链路闭环**：发布商品 → 浏览/加购 → 下单 → 支付 → 发货 → 收货 → 评价 → 售后，每一步都有真实落库与状态流转，不存在"页面能点但后端没实现"的空壳环节。
2. **C2C 双角色可用**：学生（`ry`）既能当买家也能当卖家，卖家身份由登录态强制决定，前端伪造 `sellerId` 无效。
3. **前端可视化交付**：为每个业务域提供 Element Plus 页面，且区分**运营后台视角**（商品/分类/售后管理）与**买家商城视角**（商城列表/商品详情）。
4. **权限按角色收敛**：菜单由后端 `sys_menu` 动态驱动，未授权菜单不出现在侧边栏，接口级用 `@PreAuthorize` 兜底。
5. **可被独立验证**：以 E2E 脚本（双账号、28 条断言）证明闭环可用，而非仅靠人工截图。

## 二、业务闭环全景

### 2.1 交易主链路

```
卖家                                    买家
 │ 发布商品（sellerId 强制取登录态）      
 │──────────────────────────────────────▶ 浏览商城（在售商品列表）
 │                                         │ 加入购物车
 │                                         │ 下单（原子扣库存，防超卖）
 │                                         │ 支付（原子扣余额，防透支）
 │ 发货（录入物流单号）◀────────────────────│
 │                                         │ 确认收货
 │                                         │ 评价（星级 + 内容）
 │                                         │ 申请售后（退货退款）
 │ 审核（同意 → 退款 + 回库存）────────────▶ │ 余额/库存回滚
```

### 2.2 订单状态机

订单状态常量定义于 `CampusOrderServiceImpl`，全链路只允许按既定方向流转，非法流转在服务层直接拒绝：

| 状态值 | 名称 | 可流转到 | 触发动作 |
|--------|------|----------|----------|
| 0 | 待支付 `WAIT_PAY` | 1 / 4 | 支付 / 取消 |
| 1 | 已支付 `PAID` | 2 | 卖家发货 |
| 2 | 已发货 `SHIPPED` | 3 | 买家确认收货 |
| 3 | 已完成 `FINISHED` | 5 | 买家申请售后 |
| 4 | 已取消 `CANCELLED` | — | 终态 |
| 5 | 退款中 `REFUNDING` | 6 / 3 | 卖家审核 |
| 6 | 已退款 `REFUNDED` | — | 终态 |

## 三、领域模块与接口清单

后端业务代码统一位于 `campus-tao/RuoYi-Vue-master/ruoyi-system/src/main/java/com/ruoyi/campus/`，按 `controller → service/ICampusXxxService → service/impl → mapper → domain` 五层组织，共 **10 个业务域**：

| 业务域 | 控制器 | 根路径 | 关键接口 |
|--------|--------|--------|----------|
| 商品 | `CampusProductController` | `/campus/product` | `GET /list`、`GET /{id}`、`POST`、`PUT`、`DELETE /{ids}`、`PUT /status` |
| 分类 | `CampusCategoryController` | `/campus/category` | `GET /list`、`POST`、`PUT`、`DELETE /{ids}` |
| 购物车 | `CampusCartController` | `/campus/cart` | `GET /list`、`POST /add`、`PUT /quantity`、`PUT /checked`、`DELETE /{ids}` |
| 订单 | `CampusOrderController` | `/campus/order` | `POST /create`、`POST /pay/{orderNo}`、`POST /cancel/{orderNo}`、`POST /ship/{orderNo}`、`POST /finish/{orderNo}`、`GET /list`、`GET /stats`、`GET /{orderNo}` |
| 支付账户 | `CampusAccountController` | `/campus/account` | `GET /balance`、`POST /recharge` |
| 售后 | `CampusAftersaleController` | `/campus/aftersale` | `POST /apply`、`POST /audit`、`GET /list` |
| 评价 | `CampusReviewController` | `/campus/review` | `POST`（新增）、`GET /list`（按商品）、`GET /seller`（卖家视角，sellerId 取自登录态） |
| 站内通知 | `CampusNoticeController` | `/campus/notice` | `GET /list`（按登录态隔离） |
| 外呼留痕 | `CampusNotifyLogController` | `/campus/notifylog` | `GET /list`（仅管理员，短信/邮件通道留痕） |
| 物流轨迹 | `CampusLogisticsController` | `/campus/logistics` | `GET /trace/{orderNo}`（仅本人订单） |

### 3.1 入参校验统一收敛到 DTO

M3 完成后（v1.0.15 治理）所有写接口均不再直接接收实体或裸字段，改为 `@Valid` + DTO，共 **12 个 DTO**：

| DTO | 约束要点 |
|-----|----------|
| `CampusProductCreateDTO` | 标题/价格/库存等创建字段 |
| `CampusProductUpdateDTO` | `@NotNull id` + 与创建同字段集，`@Min(0) stock` |
| `CampusProductStatusDTO` | `@NotNull id`、`@Min(0)@Max(1) status` |
| `CampusCategorySaveDTO` | `@NotBlank @Size(max=50) name`（新增/修改共用） |
| `CampusCartAddDTO` | 加购商品与数量 |
| `CampusCartQuantityDTO` | `@NotNull id`、`@NotNull @Min(1) quantity` |
| `CampusCartCheckDTO` | `@NotNull id`、`@Min(0)@Max(1) checked` |
| `CampusOrderCreateDTO` | 下单入参 |
| `CampusAccountRechargeDTO` | 充值金额 |
| `CampusAftersaleApplyDTO` / `CampusAftersaleAuditDTO` | 售后申请 / 审核 |
| `CampusReviewAddDTO` | 评价星级与内容 |

> 设计理由：把"参数是否合法"从 `if (xxx == null)` 的散落判断，前移为声明式约束。非法入参在进入业务逻辑前即被 `MethodArgumentNotValidException` 拦截，服务层只处理合法输入。

### 3.2 并发安全的两处硬约束

| 场景 | 实现 | 不变量 |
|------|------|--------|
| 下单扣库存 | `update campus_product set stock = stock - #{count} where id = #{id} and stock >= #{count}` | 受影响行数 0 即库存不足，**永不超卖** |
| 支付扣余额 | `update campus_account set balance = balance - #{amount} where user_id = #{userId} and balance >= #{amount}` | 受影响行数 0 即余额不足，**永不透支** |
| 订单号生成 | 时间戳 + `AtomicInteger` 进程内自增序列（4 位）+ `uk_order_no` 唯一索引兜底 | 同秒并发不冲突（多实例部署的已知边界见 `CampusOrderServiceImpl` 注释） |

## 四、前端页面交付

前端代码位于 `campus-tao-ui/src/views/campus/`，接口封装位于 `campus-tao-ui/src/api/campus/`（业务与框架 api 目录隔离）。

### 4.1 页面清单（10 个）

| 页面 | 路径 | 视角 | 说明 |
|------|------|------|------|
| 商品管理 | `product/index.vue` | 运营后台 | 商品 CRUD、上下架、状态筛选 |
| 分类管理 | `category/index.vue` | 运营后台 | 分类维护 |
| 购物车 | `cart/index.vue` | 买家 | 数量调整、勾选、批量结算 |
| 我的订单 | `order/index.vue` | 买家/卖家 | 状态统计卡、列表、支付/取消/发货/收货/评价动作、评价弹窗 |
| 支付账户 | `account/index.vue` | 买家 | 余额查询与充值 |
| 售后管理 | `aftersale/index.vue` | 买家/卖家 | 售后申请与审核 |
| **校园商城** | `mall/index.vue` | **买家商城** | 关键词/分类/排序筛选 + 卡片网格，仅展示在售商品 |
| **商品详情** | `mall/detail.vue` | **买家商城** | 图片相册、信息面板、加购/立即购买、商品评价与平均分 |
| **评价管理** | `review/index.vue` | **卖家** | 本人名下商品收到的评价（统计卡 + 列表） |
| 通知外呼日志 | `notifylog/index.vue` | 运营后台 | 短信/邮件外呼留痕查询 |

其中「校园商城 / 商品详情 / 评价管理」三个页面为 v1.0.15 新增的**买家侧与卖家侧旅程补全**，此前系统只有运营后台风格的页面，买家缺少"逛商品"的入口。

### 4.2 接口封装（10 个模块）

`api/campus/` 下按域拆分：`product.js`、`category.js`、`cart.js`、`order.js`、`account.js`、`aftersale.js`、`review.js`、`notice.js`、`notifylog.js`（+ 物流相关调用），全部复用若依统一的 `request` 封装与响应拦截器。

### 4.3 买家可购性判定

商品详情页通过 `canBuy` / `buyBlockReason` 计算属性在**前端提前拦截**三类不可购买情况，避免用户点了才报错：

- 自己发布的商品（防自购）
- 商品已下架（`status !== 1`）
- 库存为 0

> 前端拦截只是体验优化，**真正的强制校验仍在服务端**（E2E 断言 16/17 已验证越权与非法流转被拒）。

## 五、权限与菜单接入

### 5.1 动态菜单

菜单**不硬编码在前端**，而由后端 `sys_menu` 表驱动：登录后 `GET /getRouters` 按当前角色返回可见菜单，前端 `constantRoutes` 不再登记校园淘菜单。

校园淘菜单树（父级 `2000`「校园淘」，`menu_type='M'`）：

| menu_id | 名称 | 路径 | 组件 | 可见 | perms |
|---------|------|------|------|------|-------|
| 2001 | 商品管理 | `product` | `campus/product/index` | 是 | `campus:product:list` |
| 2002 | 分类管理 | `category` | `campus/category/index` | 是 | `campus:category:list` |
| 2003 | 购物车 | `cart` | `campus/cart/index` | 是 | `campus:cart:list` |
| 2004 | 我的订单 | `order` | `campus/order/index` | 是 | `campus:order:list` |
| 2005 | 支付账户 | `account` | `campus/account/index` | 是 | `campus:account:balance` |
| 2006 | 售后管理 | `aftersale` | `campus/aftersale/index` | 是 | `campus:aftersale:list` |
| 2007 | 通知外呼日志 | `notifylog` | `campus/notifylog/index` | 是（仅管理员） | `campus:notifylog:list` |
| **2008** | **校园商城** | `mall` | `campus/mall/index` | 是 | —（所有登录用户） |
| **2009** | **商品详情** | `mall-detail` | `campus/mall/detail` | **否（隐藏）** | — |
| **2010** | **评价管理** | `review` | `campus/review/index` | 是 | `campus:review:list` |

> 2009 为隐藏菜单（`visible='1'`）：详情页需从商品卡片跳转进入，不应出现在侧边栏，但若依路由由 `sys_menu` 驱动，必须登记才能访问。
> 按钮级权限（`menu_type='F'`）共 15 条（`2100`~`2114`），含 `campus:review:add`（评价）、`campus:aftersale:edit`（售后审核）等。

### 5.2 角色收敛矩阵

| 角色 | 校园淘目录 | 商品管理 | 分类管理 | 购物车 | 我的订单 | 支付账户 | 售后管理 | 校园商城 | 评价管理 | 外呼日志 |
|------|-----------|----------|----------|--------|----------|----------|----------|----------|----------|----------|
| `admin` | 可见 | 可见 | 可见 | 可见 | 可见 | 可见 | 可见 | 可见 | 可见 | 可见 |
| `ry`（买家/卖家） | 可见 | 可见 | 不可见 | 可见 | 可见 | 可见 | 可见（无审核按钮） | 可见 | 可见 | 不可见（403） |

### 5.3 接口级兜底

菜单控制"看不看得见"，`@PreAuthorize("@ss.hasPermi('...')")` 控制"调不调得动"。E2E 断言 17 专门验证：`ry` 直接调用管理员接口返回 **403**，证明前端隐藏不等于后端放行。

## 七、端到端验证证据

### 7.1 E2E 脚本

`campus-tao/e2e_business.py`：纯标准库实现（`urllib`，零第三方依赖），**双账号**（`admin` 卖家 / `ry` 买家）驱动全链路，共 **25 个编号步骤 / 28 条断言**：

| # | 步骤 | 验证要点 |
|---|------|----------|
| 1 | 双账号登录 | `admin` / `ry` 均可登录 |
| 2 | 买家充值 500 | 新账户行自动创建 |
| 3–4 | 卖家发布商品（伪造 `sellerId=99`） | **卖家身份被服务端强制覆盖为登录用户** |
| 5–6 | 加购 2 件 → 下单 | 买家 ≠ 卖家，自购拦截不触发 |
| 7 | 支付 | 原子扣款 60 |
| 8 | 订单归属 | `ry` 订单列表**仅含本人订单** |
| 9–9.4 | 卖家发货 | 物流单号落库可见；触发站内通知；未登录不可读通知；关键写操作入 `@Log` 审计 |
| 10–11 | 确认收货 → 评价 | 评价落库 |
| 12–13.1 | 申请售后 → 审核通过 | **审核人取自登录态，前端伪造 `handler` 被忽略** |
| 14 | 回滚断言 | 余额回滚 + 库存回滚 |
| 15 | 防超卖 | 库存 1 的商品下单 2 件**必须失败** |
| 16 | C2C 卖方能力 | 学生 `ry` 可自主发布商品，卖家身份强制为本人 |
| 17 | 权限收敛 | `ry` 调管理员接口 **403** |
| 18–18.3 | 运营能力 | 物流轨迹查询与通道降级；未登录/越权查询被拒；外呼留痕按登录态隔离（`ry` 403，`admin` 可见短信+邮件两通道留痕且关联业务号） |

通过时输出 `RESULT: ALL_PASS`，任一断言失败输出 `RESULT: HAS_FAIL` 并以非零退出码结束——可直接作为 CI 门禁。

### 7.2 浏览器实测

登录 `http://localhost:8088`（`admin/admin123` 或 `ry/admin123`）后：

- 左侧「校园淘」目录按角色展开，`ry` 看不到「分类管理」与「通知外呼日志」；
- 运营后台六个页面（商品/分类/购物车/我的订单/支付账户/售后管理）列表、表单、状态流转正常；
- 买家商城可筛选商品、进入详情、加购下单；
- 卖家「评价管理」可见本人商品收到的评价及平均分。

### 7.3 经前端代理的接口联通

`8088/dev-api` → `8080` 代理下，`/campus/product`、`/campus/category`、`/campus/cart`、`/campus/order`、`/campus/account`、`/campus/aftersale`、`/campus/review` 均正常返回。

## 八、踩坑记录

| 现象 | 根因 | 解决 |
|------|------|------|
| `npm install` 卡死 | `sass-embedded` 从 GitHub 下载原生二进制，本机不通 GitHub | 改用纯 JS 的 `sass` |
| 前端起在 80 端口失败 | 系统进程占用 80 | `vite.config.js` 端口改为 8088 |
| 前端调后端失败 | 未代理或后端未在 8080 | Vite `/dev-api` 代理到 8080 |
| 买家看不到页面 / 接口 403 | 菜单前端硬编码，无法按角色收敛 | 迁移为后端 `sys_menu` 动态菜单 + 角色授权 |
| 隐藏页面无法访问 | 若依路由由 `sys_menu` 驱动，未登记即无路由 | 用 `visible='1'` 的隐藏菜单登记详情页（`menu_id=2009`） |
| 同秒并发下单订单号重复 | 订单号仅含秒级时间戳 | 追加进程内 `AtomicInteger` 序列，并以 `uk_order_no` 唯一索引兜底 |

### 验收判定
