# 校园淘 · M4 企业级能力加固说明

在 M3 业务闭环基础上，从安全、一致性、可靠性、性能、工程化、运维六个维度加固，覆盖任务书「≥6 项企业级能力」要求。

---

## 1. 安全（Security）
- **登录鉴权**：基于 Spring Security + JWT（若依原生），写接口带 `@PreAuthorize("@ss.hasPermi('campus:xxx:xxx')")`，无权限返回 403；仅商品/分类/评价的**列表与详情**读接口保留 `@Anonymous`（便于未登录浏览商品），其余接口一律要求登录。
- **数据归属校验**：订单/购物车/售后/账户等「我的」数据接口，非管理员会被强制按当前登录用户过滤（如订单列表 `order.setUserId(userId)`），详情接口校验归属，杜绝横向越权查看他人订单。
- **登录验证码**：开关由 `sys_config.sys.account.captchaEnabled` 控制（演示环境置 `false` 方便验收，生产建议置 `true`）。
- **参数来源隔离**：当前用户身份统一从 `SecurityUtils.getUserId()/getUsername()/isAdmin()` 取；发布商品时卖家身份由服务端强制写入（前端伪造的 `sellerId` 一律忽略），售后审核人由服务端写入当前登录用户（前端传入的 `handler` 一律忽略），凡身份类字段均不信任前端传值。
- **密钥外部化**：JWT 密钥支持环境变量注入 `${JWT_SECRET:演示默认值}`，生产可通过环境变量覆盖，避免密钥硬编码进仓库。

## 2. 一致性（Consistency）
- **事务边界清晰**：下单、支付、取消、发货、确认收货、售后审核全部标注 `@Transactional(rollbackFor = Exception.class)`，任一环节失败整体回滚。
- **库存与订单一致**：下单时 `decreaseStock` 与订单落库在同一事务；取消/退款时 `increaseStock` 与余额回退、状态变更同事务，杜绝「钱退了库存没回」或「库存扣了订单没成」。

## 3. 可靠性（Reliability）
- **库存防超卖（乐观锁）**：`CampusProductMapper.decreaseStock` 用 `UPDATE ... SET stock=stock-? , version=version+1 WHERE id=? AND stock>=?`，并发下若库存不足影响行数为 0，服务层抛「库存不足」并整体回滚（已专项验证）。
- **支付幂等**：`payOrder` 对已付款订单重复调用直接返回成功，避免网络重试导致的重复扣款。
- **账户扣款原子化**：`CampusAccountMapper.decreaseBalance` 用 `UPDATE ... SET balance=balance-? WHERE user_id=? AND balance>=?`，余额不足时影响行数为 0，从根本上杜绝并发超扣；退款入账用对称的 `increaseBalance`（已由 JUnit JDBC 用例验证）。
- **售后状态机**：订单状态 `0→1→2→3`、异常 `4/5/6` 由服务层强约束，非法跃迁（如对非待付款订单支付）直接拒绝。

## 4. 性能（Performance）
- **Redis 缓存**：若依原生集成 Redis（本系统用 embedded-redis 于 6379），承担验证码、登录令牌、系统配置缓存，降低数据库压力。
- **MyBatis 分页**：列表接口走 `BaseController.startPage()` + `getDataTable()`，自动物理分页。
- **连接池**：Druid 连接池管理 MySQL 连接；嵌入 Redis 连接复用。

## 5. 工程化（Engineering）
- **分层架构**：`domain / mapper / service / controller` 清晰分层，`com.ruoyi.campus` 独立包，不污染若依原生代码。
- **统一响应**：全部接口返回 `AjaxResult`（含 `code/msg/data`），前端 `request` 拦截器统一处理。
- **统一业务异常**：业务校验失败统一抛框架 `ServiceException`，由若依全局异常处理器返回 `code/msg`；另有 `CampusGlobalExceptionHandler`（`@RestControllerAdvice`，`Ordered.LOWEST_PRECEDENCE`）兜底未预期的 `RuntimeException`，避免把堆栈抛给前端。
- **参数校验**：Controller 统一 `@Validated` + `@Valid` + DTO（`com.ruoyi.campus.dto`），用 Jakarta Bean Validation 声明式校验（如「购买数量至少为 1」「评分范围为 1-5」），非法入参在进入业务逻辑前即被拦截并返回中文提示。
- **单元测试**：`ruoyi-system/src/test/java/com/ruoyi/campus/` 提供可运行的 JUnit 5 用例（DTO 校验 11 例 + 账户原子扣款 4 例，共 15 例全部通过）。
- **代码生成友好**：实体/字段命名规范，便于后续接入若依代码生成器。

## 6. 运维（Operations）
- **健康检查**：若依原生未引入 Actuator，存活探针以 `curl http://localhost:8080/captchaImage` 返回 200 为准；数据源观测可用 Druid 自带监控页（`/druid`）。
- **日志**：业务关键步骤均有 `Logger` 记录（如全局异常处理器记录未预期异常摘要）。
- **可观测启动**：应用启动打印端口与内嵌 Redis 状态，便于排查。
- **AI 全程留痕**：`campus-tao/ai-log/001 ~ 007` 记录每一里程碑的决策、踩坑与验证结果，满足任务书「AI 辅助过程留痕」硬性要求。

## 本次加固代码改动

### M4 阶段
- 新增 `com.ruoyi.campus.exception.CampusGlobalExceptionHandler.java`（统一异常响应兜底）
- `CampusOrderServiceImpl.payOrder` 增加幂等判断（已付款直接返回成功）

### 加固阶段（P0 / P1 / P2）
- **账户扣款原子化**：`CampusAccountMapper` 新增 `decreaseBalance`/`increaseBalance`，`CampusAccountServiceImpl` 的支付/退款改走原子 SQL，消除「读-改-写」竞态。
- **越权防护**：订单 list/detail 去除 `@Anonymous` 并加归属校验；购物车/售后/账户控制器去匿名；发布商品卖家身份由服务端强制写入。
- **横向越权（IDOR）加固**：购物车改数量/勾选与删除均校验记录归属，非本人记录直接拒绝；商品修改/上下架/批量删除校验「卖家本人或管理员」；商品编辑改为字段白名单回填，不再接收 `sellerId/sellerName`，杜绝批量赋值篡改归属。
- **审核归属防伪造**：售后审核人改由服务端从登录态取（`SecurityUtils.getUsername()`），`CampusAftersaleAuditDTO` 移除 `handler` 字段，前端不再传该值。
- **菜单与前端路由**：`sys_menu`/`sys_role_menu` 补齐校园淘菜单与角色授权（目录 2000 + 菜单 2001~2006 + 按钮 2100~2114；买家角色（学生）授予发布与维护商品（2100~2102）、加购、下单、充值、售后申请、评价等必要权限，不含分类管理与售后审核），前端移除 `router` 中硬编码的 campus 路由，改由后端动态菜单驱动。
- **参数校验**：新增 7 个 DTO（`com.ruoyi.campus.dto`），6 个控制器接入 `@Validated` + `@Valid`。
- **统一异常**：3 个 ServiceImpl 的业务异常由 `RuntimeException` 改为框架 `ServiceException`。
- **密钥与路径外部化**：`ruoyi.token.secret` 改为 `${JWT_SECRET:...}`；上传路径 `ruoyi.profile` 改为相对路径 `./uploadPath`；数据库账号口令与 Druid 控制台口令改为环境变量占位符（`${DB_USERNAME:root}`、`${DB_PASSWORD:...}`、`${DRUID_LOGIN_USERNAME:...}`、`${DRUID_LOGIN_PASSWORD:...}`），源码内不再出现明文口令，生产可直接用环境变量覆盖。
- **自动化测试**：`e2e_business.py` 改造为双账号全链路（含越权、防超卖、审核人防伪造专项）并新增 JUnit 5 单元测试 15 例。
- **版本控制**：交付包初始化 Git 仓库（`main` 分支），`.gitignore` 排除内置 JDK/MySQL 运行时、`node_modules`、`target`、`uploadPath` 与日志等非源码内容。

**验证**：E2E `RESULT = ALL_PASS`；`mvn test` 15/15 通过；动态菜单权限收敛校验通过（详见 M5 测试报告）。

**构建方式说明**：发行 jar 已由 **Maven 纯净重建**（Apache Maven 3.9.9 + JDK 17，`mvn -DskipTests clean package`），外层 jar 中不含任何手工注入的 class，改动类位于内层 `BOOT-INF/lib/ruoyi-system-3.9.2.jar`，与源码构建关系一一对应、可完整重现。

在此之前，源码树存在一处**构建缺陷**：`ruoyi-system/pom.xml` 未声明编译期 `jakarta.validation` 依赖（campus 模块 DTO/Controller 与 `SysConfig`/`SysNotice`/`SysPost`/`SysUserServiceImpl` 等类均使用该 API），导致 `mvn compile` 报出 164 处「程序包 jakarta.validation 不存在」。本次已补入 `spring-boot-starter-validation`（编译作用域）修复——它与运行时 fat jar 中既有的 Hibernate Validator 9.1.0 对齐，同时移除了冗余的 test 作用域 `hibernate-validator` 声明。

**构建验收**：`mvn -DskipTests clean package` → BUILD SUCCESS（Reactor 全模块）；`mvn test` → 15/15 全绿；重建 jar 内 `application-druid.yml` 为外部化占位符、无明文口令；以该 jar 启动后 E2E `RESULT = ALL_PASS`。
