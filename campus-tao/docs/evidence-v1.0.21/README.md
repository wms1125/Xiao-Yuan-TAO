# 校园淘 · 浏览器实测截图证据（v1.0.21）

## 一、为什么要补这一轮

M5「本节未纳入」此前如实记录：**浏览器实测证据停留在 v1.0.15 之前**——v1.0.16 ~ v1.0.20 新增/落地的页面（收货地址、我的收藏、消息沟通、购物车结算联动、商品管理）一直没有截图级证据。

项目自定《AI-辅助开发规范》的原则是「产出即证据」。这些页面的**行为**已有 197 例前端用例 + 五道门禁 + e2e 接口级断言覆盖，但缺的是最直观、也最无法用断言替代的那一层：**页面在当前这份代码上，确实能被浏览器渲染出来**。

本轮把场景从 6 个补齐到 11 个，覆盖 v1.0.16 ~ v1.0.21 的全部新增页面。

登录账号：`ry` / `admin123`（买家角色）。

## 四、核验结论

**1. 登录确实成功（而非停在登录页）**
填入 `ry` / `admin123` 点击「登 录」后，`agent-browser get url` 回显 `http://localhost:8088/index`——已离开 `/login`，说明鉴权通过。

**2. 每个路由都回显自身路径，无一被弹回登录页**
逐页 `get url` 的结果与清单第三列完全一致（如 `…/campus/address` 回显 `…/campus/address`）。若会话失效或菜单未授权，依若依的路由守卫会被重定向回 `/login`——**没有发生，即证明会话有效且这批菜单对买家角色可见可达**。

**3. 文件体积无异常小值（先排除"空白页"）**
11 张体积 33 ~ 323 KB。纯空白页的 PNG 通常只有几 KB，故先以体积做初筛。

## 五、两点需要说明的观察（避免被误读为缺陷）

1. **截图中商品缩略图显示「无图」占位**。这些行是 e2e/压测过程中**创建出来的测试商品**（命名如「限量1件测试163160」「学生发布测试163160」），它们本身不带封面图，故走占位图分支。这是**测试数据的属性，不是图片链路缺陷**——随包交付的 11 张品类实拍图位于 `campus-tao-ui/public/campus-img/`，供种子数据商品使用。
2. **空态页面（收藏、消息）看起来"没内容"是正确表现**：`ry` 账号在当前演示库中确实没有收藏与会话。空态文案与引导语正常渲染，恰恰是空态分支被覆盖的证据；若渲染中断则会得到空白内容区（v1.0.1 曾出现过的那类问题），而不是这段引导文案。
