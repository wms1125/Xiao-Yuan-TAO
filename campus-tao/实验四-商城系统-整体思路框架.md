## 二、分层与模块划分

### 2.1 后端分层

| 层 | 职责 | 关键约定 |
|----|------|----------|
| controller | 接收请求、参数校验、权限注解、返回 `AjaxResult` | 写接口标注 `@PreAuthorize` |
| service | 业务编排、事务边界、状态机约束 | `@Transactional(rollbackFor = Exception.class)` |
| mapper | 数据访问（MyBatis） | 自定义乐观锁/原子扣款 UPDATE |
| domain / dto | 实体与传输对象 | DTO 承载 Jakarta Bean Validation 校验 |
| exception | 异常与全局处理 | 业务异常 + `@RestControllerAdvice` 兜底 |

业务统一置于 `com.ruoyi.campus` 独立包，分 `domain` / `mapper` / `service` / `controller` / `dto` / `exception`，不污染若依原生代码。

### 2.2 模块划分

| 模块 | 接口域 | 覆盖能力 |
|------|--------|----------|
| 商品 | `/campus/product` | 发布/编辑/删除/上下架/浏览 |
| 分类 | `/campus/category` | 树形分类维护 |
| 购物车 | `/campus/cart` | 加购/改数量/删除/结算 |
| 订单 | `/campus/order` | 下单/支付/取消/发货/收货 |
| 支付账户 | `/campus/account` | 沙箱余额/充值 |
| 售后 | `/campus/aftersale` | 申请/审核（通过则退款并回补库存） |
| 评价 | `/campus/review` | 订单评价 |

### 2.3 前端模块

| 目录 | 说明 |
|------|------|
| `campus-tao-ui/src/views/campus/` | 六个业务页面：product / category / cart / order / account / aftersale |
| `campus-tao-ui/src/api/campus/` | 对应接口封装 |
| 菜单 | 不再硬编码于前端路由，改由后端菜单表动态驱动 |

## 三、技术路线

1. **底座先行**：以若依 RuoYi-Vue 3.9.2 为底座，直接复用登录鉴权、用户角色菜单、日志监控等能力。
2. **业务独立**：校园淘业务全部落在 `com.ruoyi.campus` 独立包与 `views/campus`、`api/campus` 目录，与框架代码物理隔离。
3. **闭环驱动**：以「发布 → 浏览 → 加购 → 下单 → 支付 → 发货 → 收货 → 评价 → 售后」闭环为主线组织开发，先后端后前端。
4. **加固收口**：闭环跑通后，从安全、一致性、可靠性、性能、工程化、运维六个维度做企业级加固。
5. **证据留痕**：以可执行的 E2E 脚本与单元测试作为验证证据，全过程记录在 `ai-log/`。

## 四、业务闭环设计思路

### 4.1 正向链路

```
发布商品 → 加入购物车 → 去结算（下单，预占库存）
        → 支付（沙箱扣余额）→ 发货 → 确认收货 → 评价
```

### 4.2 逆向售后链路

```
订单「申请售后」→ 售后管理「审核通过」→ 自动退款（余额回滚）+ 自动回补库存
```

### 4.3 订单状态机

```
0 待付款 → 1 已付款/待发货 → 2 已发货 → 3 已完成
                     ↘ 4/5/6 异常态（取消/售后中等）
```

状态跃迁由服务层强约束，非法跃迁直接拒绝。

### 4.4 闭环设计的关键取舍

| 关注点 | 取舍 | 说明 |
|--------|------|------|
| 支付 | 沙箱模拟而非真实通道 | 符合实验「模拟支付」要求，聚焦业务闭环 |
| 库存 | 下单即预占，扣减与订单同事务 | 保证不出现「库存扣了订单没成」 |
| 退款 | 审核通过时余额回退与库存回补同事务 | 保证资金与库存双向一致 |
| 操作归属 | 一律取自服务端 `SecurityUtils` | 前端无法篡改下单/支付/评价归属人 |

## 五、企业级能力设计思路（六维）

| 维度 | 设计思路 | 落点 |
|------|----------|------|
| 安全 | Spring Security + JWT 鉴权；写接口 `@PreAuthorize`；身份取服务端；归属校验；验证码开关化；JWT 密钥可注入 | controller / 配置 |
| 一致性 | 关键动作统一 `@Transactional(rollbackFor)`；库存与订单同事务；退款与回补同事务 | service |
| 可靠性 | 防超卖乐观锁；支付幂等；账户原子扣款防超扣；状态机约束 | mapper / service |
| 性能 | Redis 缓存（验证码/令牌/配置）；MyBatis 物理分页；Druid 连接池 | 缓存 / 分页 / 连接池 |
| 工程化 | 四层分层；统一 `AjaxResult`；全局异常兜底；DTO + Bean Validation（中文提示） | 全局 / dto |
| 运维 | 存活探针以鉴权接口返回 200 为准（未引入 Actuator）；关键日志留痕；启动期打印端口与内嵌 Redis 状态；ai-log 全程留痕 | 监控 / 日志 |

> 详细说明见 `M4-企业级能力加固.md`。
